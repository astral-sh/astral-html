# Performance

The benchmark compares parsing and uv's HTML field extraction with
`astral-tl` 0.8.0. It verifies equal extracted output before measuring each
input. Both implementations run in the same executable and use the same
allocator. URL handling, package validation, network requests, and resolution
are outside the measured work.

## Hardening results

The run after adding the attribute budget and allocation fixes measured
**0.90–2.33×** the performance of astral-tl across the six uv index workloads
with jemalloc. Four were faster; CodeArtifact and the flat-index fixture took
about 11% longer. Recovering that performance remains open work.

| Input | astral-html (µs) | astral-tl (µs) | Speedup |
| --- | ---: | ---: | ---: |
| PyPI iniconfig (captured) | 12.02 | 17.22 | 1.43× |
| CodeArtifact (uv fixture) | 3.29 | 2.95 | 0.90× |
| Flat index (uv fixture) | 1.97 | 1.78 | 0.90× |
| Project index, 1,000 links (generated) | 925.24 | 1,337.28 | 1.45× |
| Project index, 10,000 links (generated) | 11,018.37 | 25,715.82 | 2.33× |
| Root index, 10,000 links (generated) | 4,524.32 | 8,932.31 | 1.97× |
| 64 extra attributes per link (generated) | 815.86 | 845.47 | 1.04× |
| 1 MiB text node (generated) | 20.64 | 19.68 | 0.95× |
| 1,000 links with entities (generated) | 1,186.62 | 1,376.21 | 1.16× |

The [timing summaries](benchmarks/2026-10-04-hardening-jemalloc.csv)
and [environment, binary, and source hashes](benchmarks/2026-10-04-hardening-environment.json)
identify the tested implementation. A speedup below 1 means astral-html took
longer. The system allocator was not rerun for this change.

## Baseline before hardening

Before hardening, the six uv workloads measured **1.04–2.43×** faster with
jemalloc, with margins as small as 5%. The system allocator regressed on
CodeArtifact and the root index; the 1 MiB text case was slower with both
allocators. The [system results](benchmarks/2026-10-04-system.csv),
[jemalloc results](benchmarks/2026-10-04-jemalloc.csv), and
[source hashes](benchmarks/2026-10-04-environment.json) retain that baseline.

## Method

The recorded runs used an AMD EPYC-Milan Linux host, pinned to CPU 24,
with Rust 1.98.1-dev (`ohm-1.98.1-1`), ThinLTO, one codegen unit, and Ohm's
experimental defaults disabled. Both parsers use exactly the same build
settings. The jemalloc executable uses `tikv-jemallocator` 0.6.1, from the same
dependency series uv uses on supported Linux architectures. The other
executable uses the system allocator.

Each case warms both implementations for a combined 100 ms to choose a common
iteration count, then takes 31 samples per implementation. Measurement order
alternates each sample. The table uses median runtime; the raw CSV files also
retain 10th and 90th percentile sample runtimes. These percentiles describe
variation between samples, not confidence intervals. Input creation and output
comparison happen outside the timed loop. Parsing, lookup, entity decoding,
owned field extraction, and destruction happen inside it.

The nine cases run in the same fixed order in each executable. The captured
iniconfig response and uv's CodeArtifact and flat-index test inputs have pinned
provenance and licenses. The larger indexes, attribute-heavy input, long text
node, and entity-heavy input are generated by the harness. They are not
production traffic captures.

Results apply to the recorded source hashes, host, inputs, and allocator.

## Reproduce

```console
ASTRAL_HTML_BENCH_SAMPLES=31 cargo bench -p astral-html --bench parse
ASTRAL_HTML_BENCH_SAMPLES=31 cargo bench -p astral-html --bench parse --features benchmark-jemalloc
```

The harness defaults to a 100 ms combined warmup. Set
`ASTRAL_HTML_BENCH_SAMPLE_MS` to change it. On Linux, use `taskset -c <cpu>` to
pin the executable to an available logical CPU. When using Ohm locally, use
`cargo +ohm -Zohm-defaults=no bench` and unset the procedural-macro and native-tool
trust overrides for the measurement build.

The executable measures timings only with `--bench`, which `cargo bench` passes
automatically. Running it without that argument, or with `--test`, checks all
outputs and skips timing. This also keeps `cargo test --all-targets` fast. CI
checks correctness without imposing a wall-clock threshold on shared runners.
